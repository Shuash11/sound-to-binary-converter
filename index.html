Explain It

  1. 1How does your app change a sound wave into binary?

    It samples the wave's height at equal time steps across one period, rounds each height to the nearest level, then writes each level in binary with leading zeros. Every row in the samples table above walks through those three steps for one sample.

  2. 2Run Test A again with 2 bits, then 6 bits. Which gives more detail about the wave, and why?

    I re-ran Test A both ways: with 2 bits all eight heights get squeezed onto just 4 levels (22), but with 6 bits there are 64 levels (26), so each height lands much closer to its real value, and 6 bits gives far more detail. The trade-off is size: 48 total bits instead of 16.

  3. 3Which test has the longest wavelength? How is wavelength connected to frequency?

    Test B, because its 200 Hz is the lowest frequency of the three, which gives it the longest wavelength at 1.72 m. Wavelength is 343 ÷ frequency, so the relationship is inverse: higher frequency, shorter wavelength (440 Hz → 78.0 cm, 500 Hz → 68.6 cm).

  4. 4What was the hardest stage to build, and how did you fix it?

    Stage 4, turning levels into binary, was the hardest: heights that land exactly halfway, like Test A samples 1 and 5 sitting right on 3.5, must round UP to 4 (giving 100, not 011), and every value needs exactly the right number of digits with leading zeros. I fixed it by using Math.round with toString(2).padStart(bits, '0'), never toFixed, which rounds halfway floats differently, then re-ran every dataset against the Check-Your-Work table and the answer key until the output matched exactly.
